4. 설계 요점

4.1 RenderFrame 확장

  • DrawItem: 월드 행렬은 값으로(계층 월드는 엔진에서 계산), 재질 데이터와 안정 키, 기존 bones 유지. 포인터 키(Mesh*/Material*) 정렬은 안정 ID 정렬로 바꿉니다. 그대로 두면 실행마다 순서가 달라집니다.
  • RenderFrame: 카메라 위치, 광원 배열, 환경(스카이박스·IBL 이름·노출·톤매핑·앰비언트), clear color. 그림자 영역(중심·크기)은 Sherlock이 (0, 2, 0), 직교 60, 맵 2048²로 고정했으므로 파라미터로 노출합니다.
  • Scene 의존이던 InvalidateScene은 구역 교체 시 렌더러 캐시를 비우는 명시적 호출로 바꿉니다.
  • 새 렌더 관련 컴포넌트가 생기면 ComponentRegistry에 등록하고, 컴포넌트는 객체당 타입 하나만 붙일 수 있습니다. 정리 콜백(OnDestroy)은 noexcept이며 GPU 자원 해제는 렌더러가 소유합니다.

4.2 캐시와 수명

Nereides의 weak_ptr + expired() 정리 방식을 메시·재질 캐시에 모두 유지합니다. 주소 재사용으로 옛 GPU 버퍼가 돌아오는 사고를 막기 위해, 기존 객체 수정이 아니라 새 불변 데이터로 교체하는 테스트를 추가합니다.

4.3 스키닝 범위 정정

  • 이미 있음: 정점 bones/weights, 뼈 팔레트 128(127 + fallback), DrawItem::bones, 뼈 행렬 계산.
  • 새로 필요: (a) 그림자 VS 스키닝(ShadowVertexShader.hlsl:13-14), (b) 별도 뼈 상수버퍼(b4)와 Renderer.cpp:528-535의 cbuffer 이름 목록·바인딩·해제 추가(자동 반영 아님), (c) RHI 정점 의미 확장: VertexSemantic에 BlendIndices/BlendWeight, Format에 R32G32B32A32_UINT를 추가하고 D3D11Convert.cpp에 매핑(속성 7개는 상한 8 이내).
  • 그림자 패스도 같은 포즈를 읽도록 하고, 두 패스가 어긋나지 않는지 확인합니다.

4.4 행렬 규약

Sherlock 셰이더를 그대로 쓰므로 렌더러가 업로드 시 전치합니다(RenderFrame은 전치 안 된 XMFLOAT4X4). 뼈 행렬은 전치 업로드 또는 row_major 선언 중 하나로 통일하고, 첫 스키닝 모델에서 눈으로 확인합니다.

4.5 프레임 흐름과 UI 계약 (Q8, Q9)

  • 순서: RenderScene(그림자 → 메인) → 호스트의 BeginUIPass → ImGui → EndUIPass → Present.
  • EndUIPass가 renderPasses/barriers를 채우므로 값은 한 프레임 늦게 보입니다. 호스트가 매 프레임 호출해야 하고, 이를 계약으로 문서화합니다.
  • 렌더러가 ID3D11Device*/ID3D11DeviceContext* 접근자를 유지하고 ImGui가 사용합니다. 해제 순서는 Application 소멸자에서 EndPlay → 렌더러 해제 순으로 명시합니다.

4.6 셰이더와 경로

  • 컴파일은 RHI/DXBC/ShaderCompiler.cpp(LoadOrCompile, 128-171). Debug는 소스·Common.hlsli가 더 새로우면 컴파일, Release는 .cso를 쓰고 없으면 경고 후 런타임 컴파일로 폴백합니다.
  • 핫리로드는 Debug에서만, 벽시계 0.5초 폴링, 감시 파일 6개.
  • 경로는 Sherlock Paths(엔진 루트 마커 탐색)를 Nereides 규칙(실행 파일 기준 프로젝트 루트 또는 배포 data)으로 대체하고, scripts/package.ps1에 셰이더 복사를 추가합니다.
  • 직교 투영: 렌더러는 projection 행렬만 쓰므로 Nereides가 직교를 필요로 할 때만 스카이박스 VS의 proj._44 분기를 씁니다. 현재 범위에서는 코드를 그대로 가져오되 사용 여부는 필수가 아닙니다.

4.7 정점·모델

MeshVertex에 tangent(float4) 추가, 정점 색은 RGBA/RGB 중 하나로 통일(스킨 포맷도 같은 단일 포맷). 탄젠트가 0이어도 크래시는 없고 노멀맵만 틀어지므로(SafeNormalize 폴백 (1,0,0)) 로더 생성이 빠졌는지는 시각 검증으로 잡습니다.

4.8 스타일

옮긴 파일은 clang-format, BOM 제거, LF(`.vcxproj` 계열은 CRLF)로 즉시 정리합니다. Sherlock은 탭·BOM입니다.

6. 검증

  • 매 단계: 빌드, scripts/verify.ps1(Debug/Release), 모드 8종(--engine-tests, --editor-workflow-test, --smoke-test, --scene-smoke-test, --editor-smoke-test, --presentation-smoke-test, --resize-smoke-test, --editor-resize-smoke-test), --model-test. 이 작업 환경에서는 verify.ps1이 Start-Process 실행에서 실패하므로(기준선에서도 동일, docs/stages/12-renderer-rhi-port.md 참고) 같은 모드를 직접 실행해 확인합니다.
  • 기존 기준: 픽셀 임계 > 150(D3D11Renderer.cpp:545)와 pixelHash는 4단계에서 한 번 갱신합니다.
  • 추가 테스트: 메시·재질 교체 시 캐시 정합, 탄젠트 유무, 뼈 행렬 방향(스키닝), 메인·그림자 포즈 일치, 광원 8개 초과 로그, 0크기 윈도우.
  • 성능: RTX 3060 FHD 60FPS 목표. 기존 16.68ms는 VSync 켠 값이라 여유 판단 근거가 아니므로, 측정은 VSync를 끈 상태와 켠 상태를 모두 기록합니다.
