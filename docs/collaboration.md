# Git 협업 초기 안내

로컬 저장소의 기본 브랜치는 main이다. 사용자 지정 주소 `https://github.com/jung-seung-hwan/Nereides-Engine.git`을 origin으로 등록했다. 2026-10-01 원격 HEAD 조회는 성공했으며 커밋이 반환되지 않았다. push와 공개 범위 설정은 하지 않았다. 현재 준비·구현 파일은 검토 가능한 미커밋 상태다.

- 엔진 담당: 실행, 창, 입력, 공통 진단과 자원 수명.
- 렌더링 담당: DX11 렌더링 기능. 장치·컨텍스트 접근 경계는 엔진 담당과 먼저 맞춘다.
- 콘텐츠 담당 2명: 기획과 게임 데이터·에셋. 두 담당자의 구체적인 업무 구분은 후속 협의한다.
- 작업별 feature 브랜치를 사용하고 main 반영 시 변경 목적, 확인 방법, 남은 문제를 기록하는 방식을 제안한다.
- 소스, 빌드 설정, 의존성 manifest/버전, 기술 문서는 추적한다. 개인 IDE 상태와 빌드·설치 캐시는 제외한다.
- 현재 빌드는 VS2022 솔루션 방식이다. 루트의 NereidesEngine.sln을 열고 Debug 또는 Release / x64로 실행한다. .sln, .vcxproj, .vcxproj.filters를 공유하고 bin/, obj/, .vs/, .vcxproj.user는 제외한다. CMake 설정은 제거했다.
- 외부 DLL/lib는 확장자로 일괄 제외하지 않았다. 필요한 배포 파일은 출처·라이선스와 함께 판단한다.
- MMD 폴더는 /MMD/ 규칙으로 Git 추적에서 제외한다. 각 팀원이 로컬에 별도로 준비하며 기존 파일은 보존한다.
- 기존 기획·이미지 자료는 보존했다. 에셋 크기와 재배포 권한을 확인한 뒤 Git 추적 및 LFS를 결정한다. 아직 이 자료를 stage하지 않는다.
- 참조 코드 재사용은 기술검토서에 출처·이유·의존성을 남긴다.

현재 .gitignore와 .gitattributes는 Windows C++ 작업의 기본 준비다. 팀의 빌드 경로와 에셋 정책에 맞춰 단계적으로 조정한다.
