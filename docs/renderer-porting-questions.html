렌더러 포팅 협의 질문지

대상: docs/renderer-porting-plan.html · Sherlock 렌더러 → Nereides 포팅 · 제안은 이견이 없으면 그대로 진행하자는 기본값입니다.

A. 데이터 계약 (RenderFrame)

Q1PBR 재질을 어디까지 넘길까요?

Model.cpp:459는 현재 baseColor만 DrawItem::tint로 넘김. MaterialData에는 텍스처 이름 2개가 있음.

Q2서브메시를 어떻게 표현할까요?

Nereides는 파트당 MeshData 하나(indexStart 없음), Sherlock은 indexStart/Count 범위.

Q3텍스처는 어떤 형태로 전달할까요?

현재 Nereides는 텍스처 이름만 있고 로드하지 않음. (문서 §6.1 안 a/b)

Q4카메라와 에디터 뷰 계약은?

RenderFrame에는 view/projection만 있고 카메라 위치가 없음. 에디터는 Application.cpp:219의 ApplyView(frame)로 프레임을 직접 덮어씀.

Q5광원·환경·clear color는 어떻게 넘길까요?

셋 다 현재 RenderFrame에 없음.

Q6정점 포맷은 어떻게 할까요?

Nereides MeshVertex는 정적/스킨 구분 없이 bones/weights를 항상 가짐. Sherlock은 64B(탄젠트 포함).

Q7뼈 데이터 중복 정의 정리

DrawItem::bones가 이미 있는데 문서 §6.1/§6.3은 추가 항목처럼 적혀 있음.

B. 프레임 루프와 소유권

Q8Present와 UI 패스는 누가 호출할까요?

Nereides는 RenderScene 안에서 overlay 후 Present(1,0). Sherlock은 Render 밖에서 BeginUIPass/EndUIPass.

Q9D3D 장치 소유권을 옮길까요?

Device()/Context() 접근자가 이미 있음 (D3D11Renderer.h:37-45).

Q10핫리로드 폴링 시계는?

RenderFrame.time은 m_time.combat.elapsed라 일시정지 때 멈춤.

Q11스레딩 정책은?

입력~렌더가 모두 Application.cpp 루프의 단일 스레드. 문서에는 정책 없음.

Q12최소화/0크기 정책은?

Application.cpp:102-112에서 이미 Update와 Render를 건너뜀. 문서 R04는 "미정".

C. 검증과 빌드

Q13검증 기준은 어떻게 갱신할까요?

smoke-test 픽셀 임계(D3D11Renderer.cpp:545의 > 150)와 pixelHash는 PBR/IBL 도입 후 값이 바뀜.

Q14빌드 변경에 동의하시나요?

현재 vcpkg: assimp, nlohmann-json, imgui(dx11/win32), imguizmo.

D. 문서 정정 요청

  • §6.3의 "VertexTypes.h 하나"가 Sherlock 기준인지 Nereides 기준인지 명시 (Nereides에는 해당 파일 없음).
  • 성능 수치 16.68ms는 VSync 켠 값(60Hz 상한)이라 여유 판단 근거로 부족. VSync 끄고 재측정 필요.
  • "기술검토서 v1.6"이 어느 문서인지 확인 (Nereides docs/technical-review.md와 이름 중복).
  • 브랜치 feat/Renderer 원격 존재, codex/engine-foundation 삭제 여부 확인.
코드 위치는 문서 분석 중 확인된 값이며, 최종 반영 전 재확인이 필요합니다. 선택값은 이 페이지를 새로 고치면 초기화됩니다.
