# 엔진 구현 범위

## 후속 변경 기록

아래 본문은 01~08단계를 작성한 v1.5 기준의 역사적 범위다. 이후 제공된 v1.6은 고정 60Hz tick·영속 객체 구역 교체·오디오 WE07 등을 추가/변경했다. 기존 완료 상태가 v1.6 전체 충족을 의미하지 않는다. 현재 구현과의 차이는 단계별 후속 작업으로 추적한다.

2026-10-06 사용자 요청으로 에디터 합격 기준을 “팀원이 모델을 찾고 배치하고 수정·복구·저장할 수 있다”로 확장했다. 독립 뷰포트, 편집 카메라, 축/격자, 모델 검색·파일 선택·드래그 배치, XYZ 편집·Undo/Redo, Play/Stop 복구, 저장/열기·미저장 보호를 포함한다. 자세한 구현·검증과 범위는 [10단계](stages/10-editor-workflow.md)를 따른다. 이 결정은 게임 전투 수치나 미구현 v1.6 항목을 자동 확정하지 않는다.

검토일: 2026-10-06. 정승환의 공통 엔진 담당 범위를 정리한다. 기능 포함 여부는 아래 기준으로 잡고, 자료형·수치·미정 예외는 별도 계약으로 남긴다. 이 문서는 기존 합의를 정리한 구현 기준이며 새로운 팀 합의나 호환 시험 완료를 의미하지 않는다.

## 검토 시작 시점 구현 상태

아래는 구현에 착수하기 전의 기록이다. 이후 단계별 구현·검증 현황은 [구현 로드맵](implementation-roadmap.md)을 따른다.

`src/Main.cpp`, `src/Platform/Win32Window.*`, `src/Graphics/D3D11Renderer.*`, `TriangleShaders.h`를 확인했다. Win32 창·메시지 루프, DX11 초기화·리사이즈·Present, 삼각형 표시와 smoke-test 경로가 있다. 게임용 입력·시간 서비스, Scene·Component·Transform·Camera, 모델 로더·애니메이션·충돌·에디터는 아직 없다. Main의 경과 시간은 자동 테스트 종료용이며 게임 시간 서비스가 아니다. 이번 검토에서 빌드를 다시 실행하지 않았다.

| 디버그와 이벤트 수명 | 공통 로그, 실제 판정 기반 Debug Draw 연결, 상태 조회, 이벤트 해제·이전 실행 무효화 | 리소스 경로·객체·공격·전환 식별로 문제 추적. 재시작 후 이전 이벤트가 새 전투에 적용되지 않음 |
| 2D 및 전환 지원 | 재사용 가능한 2D 재생 시간·종료·스킵·취소, 페이드 요청/완료와 지역 준비 상태 연결 | 자연 종료·스킵이 한 번만 완료. 준비 실패를 성공 처리하지 않음. 전환 순서 결정은 보스 담당, 화면 표시는 렌더 담당 |

Assimp는 우선 검증 대상으로 정해졌으며 에셋 호환이 확정된 상태는 아니다. 대표 모델·모션 시험 후 채택한다. FBX 입력 채택은 모든 FBX 기능이나 MMD 특수 변형 지원을 의미하지 않는다.

## 담당 경계

| 담당 | 소유하는 구현 |
| --- | --- |
| 정승환 엔진 | 공통 실행·객체·입력·시간·CPU 리소스·재생·충돌 후보·편집·직렬화·수명·렌더 입력 수집 |
| 고성현 렌더 | DX11 장치·GPU 자원·그림자/메인/UI 출력, GPU 스키닝, 재질·조명·바다·비·안개·효과·2D/페이드 표시 |
| 유상준 플레이어 | 이동·갑판 경계 적용·카메라 동작, 약약강·검 궤적 데이터·입력 예약, 회피·패링·강화·R·피격·HUD |
| 김진우 보스 | 촉수·패턴·공용 Stagger·약점·보상·공격체, HP 경계·탈출·구역 준비·승패·재시작 흐름 |

엔진은 공격체 파괴와 피격의 후보를 묶어 제공하고, 콘텐츠는 같은 시점의 공격체 파괴 우선 규칙을 적용한다. 사망과 승리·탈출의 우선순위도 콘텐츠에서 결정한다. 특정 보스 규칙을 공통 충돌 시스템에 넣지 않는다.

렌더 포팅 때 현재 삼각형용 DX11 소유권을 정리한다. 엔진은 실행 흐름을 조정하고 렌더 모듈이 장치·스왑체인·GPU 리소스를 소유하는 문서의 연결안을 기준으로 삼는다. Present의 실제 호출 위치와 해제 계약은 두 담당자가 맞춘다.

오디오 재생·음원 확보 담당은 원문에서도 미정이다. 공통 결과 이벤트 연결은 포함하지만 오디오 시스템 전체를 엔진 담당에 자동 배정하지 않는다.

## 제공 순서와 마감별 합격 기준

1. **콘텐츠 착수 기반:** 객체·컴포넌트·Transform·입력·시간·로그와 최소 사용 예제. 임시 객체의 생성·이동·카메라 연결·삭제를 같은 실행 파일에서 확인한다.
2. **표시와 에셋 경로:** 렌더 입력 계약, 정적 모델 하나와 대표 스킨 모델/모션 하나. CPU 로딩·GPU 표시·재생 합격을 구분한다. 이 시험은 전체 에디터 완성 전에 진행한다.
3. **첫 전투 연결:** 검 궤적·판정 활성/종료·후보 묶음·Trigger·디버그. 콘텐츠가 한 타격, Stagger→약점 노출→파괴→복귀, 공격체 한 종류를 연결한다.
4. **시연 도구와 반복 실행:** 최소 편집·모델 배치·수치 변경·저장/로드, HUD 연결과 전체 재시작 정리. 2026-11-23 시연은 한 구역의 핵심 사이클과 일반 회피까지 검증한다. 패링·저스트 회피 강화·R·두 구역 전환은 이 시연의 필수 합격 항목으로 추가하지 않는다.
5. **최종 완주 지원:** 콘텐츠의 패링·강화·R 연결, 세 구역과 두 번의 2D 전환, 시간 경계·상태 유지·재시작 검증. 2026-12-16 내부 완료, 12-18 발표 기준이다.

각 단계는 코드와 함께 사용 예제·재현 장면·검증 방법·알려진 미정 사항을 제공한다. 기능별 달력 날짜는 아직 확정하지 않는다. 기술검토서의 객체 24~40인시, 로더 24~40인시, D절 엔진 분량 52~88인시를 전체 엔진 견적으로 오해하면 안 된다. 재생기·에디터·연결 등 별도 비용과 중복 여부를 검토해야 한다.

## 이번 범위에서 제외하거나 후순위로 둘 것

기획상 제외·보류: Q 스킬, 총·조준·락온·자동 방향 보정, 공격체 반사, 그래플링 훅, 자유 점프·공중 콤보, 실시간 촉수 절단, 실제 부력·배 물리, 실시간 배 간 3D 비행·착지, 엄폐물, 멀티플레이·오픈월드. 게임패드·별도 튜토리얼은 추가 목표다.

엔진 확장 후순위: ECS 전환, 범용 물리 엔진·공간 분할, 멀티스레드·비동기 로딩, 독자 바이너리 캐시, Hot Reload, 상세 Profiler, 고급 재질·애니메이션 제작 도구. 단순 프레임 시간·메모리 측정과 오류 진단은 남긴다. DX12·Deferred·FFT 바다 등은 현재 엔진 시연의 선행 조건으로 삼지 않는다.

원문에서 미정인 항목을 구현 편의로 확정 규칙으로 바꾸지 않는다. 임시값은 데이터와 검증 기록에서 표시한다. 특히 탈출 기한과 같은 시각의 진입은 성공이지만, 약점 파괴와 만료의 동률에는 이 규칙을 전용하지 않는다.

## 필수 회귀 장면

- 객체 갱신 중 제거, 동일 모델 공유 객체 중 하나 제거, 여러 번 전체 재시작 후 객체·이벤트·GPU 참조 잔존 확인.
- 낮은 프레임률에서도 공격 활성/종료와 검 궤적·표시 일치, 공격 종료 후 추가 피해 없음.
- 같은 시점의 공격체 파괴/피격과 사망/승리·탈출 결과가 후보 순회 순서에 따라 바뀌지 않음.
- 탈출 기한 직전·정확히 같은 시각·직후 진입, 일시정지·슬로모션의 시간 규칙 확인.
- 자연 종료/스킵/늦은 완료 통지/지역 준비 실패/재시작으로 전환을 반복해 입력 조기 복구·암전 잔존 확인.
- 저장/로드 후 배치·전투 설정 복원, 리소스 누락 원인 표시, 리사이즈·최소화·포커스 복구 확인.

RTX 3060 FHD 60FPS는 원문의 초기 목표다. 이번 검토에서 성능 달성이나 전체 일정의 실현 가능성을 검증한 것은 아니다.
