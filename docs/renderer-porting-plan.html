1. 결론

포팅은 가능합니다. 다만 Renderer.cpp 하나가 아니라 RHI 계층, CPU 데이터 타입(Material, Light, 서브메시), 셰이더, 텍스처 로더를 한 묶음으로 옮겨야 합니다. 스키닝은 Sherlock에 없으므로 새로 만듭니다.

  • 좌표계와 행렬 규약이 같습니다. 둘 다 왼손(LookAtLH, PerspectiveFovLH), row-vector, HLSL mul(v, M)입니다.
  • 툴체인이 같습니다. Windows, C++20, DX11, VS2022 v143, vcpkg, ImGui, ImGuizmo, nlohmann-json.
  • 백버퍼 R8G8B8A8, 깊이 D24_UNORM_S8_UINT로 포맷이 같습니다. Sherlock 렌더러가 이 포맷을 하드코딩하므로 호환됩니다.
  • 팀 문서가 이 포팅을 이미 예정했습니다. integration-contracts.md는 "Sherlock의 Renderer/BuildDrawList 입력을 RenderFrame 경계에 맞춰 바꾼다"고 적었습니다.
  • Sherlock Renderer.cpp는 Scene·Camera·GameObject에서 읽는 것이 한정되어 있고 D3D 타입이 없어서(전부 RHI 핸들) 경계를 자르기 쉽습니다.

2. 팀 문서와 현실의 차이 팀에 알릴 것

기술검토서 v1.6(10/12)은 Sherlock이 Blinn-Phong과 PCF 그림자를 가진 상태를 기준으로 쓰여 있습니다. 그러나 Sherlock은 2026-10-08에 PBR(metallic-roughness), HDR 큐브맵 IBL, 스카이박스, 톤매핑으로 바뀌었습니다(커밋 18a3bee 등).

  • WR05(조명·PBR·HDR 톤매핑, 12/10 완주 필수)의 상당 부분을 포팅이 앞당겨 해결합니다. 기술검토서는 PBR을 "신규 확장", IBL을 "추가 등급"으로 분류했습니다.
  • 스카이박스는 세 기획 문서 어디에도 없습니다. 포팅하면 따라오는 기능이므로 쓸지 팀에 알립니다.
  • 셰이딩 스타일(툰 여부), PBR용 추가 맵 세트, 최대 뼈 수는 문서에 없습니다. 아트 담당과 합의가 필요합니다.
  • 그림자는 기술검토서에서 "시연 필수"(§202)인데 "통합 목표"(§139, §308)로도 표기되어 있습니다. 시연(11/23)에는 필요하다고 보고 일정을 짭니다.
  • 문서끼리 일정도 다릅니다. 기획서는 바다·폭풍·HUD 통합을 11/21~30, 기술검토서 WR05는 12/10입니다. 기획서가 렌더 우선순위를 기술검토서에 따르도록 했으므로 기술검토서를 기준으로 삼습니다.

6. 고쳐야 할 점

6.1 RenderFrame 경계 확장 엔진 담당과 합의 · 사전 조율 대상

렌더러는 RenderFrame만 받습니다. 추가할 입력은 다음과 같습니다.

  • 재질: PBR 파라미터와 텍스처 참조. DrawItem이 재질 데이터를 가집니다.
  • 광원: LightData 배열(최대 8개, 초과분은 현재 조용히 잘림). 그림자는 광원 0이 방향광일 때만 켜집니다.
  • 환경: 스카이박스, IBL 이름, 노출, 톤매핑, 앰비언트, clear color.
  • 서브메시 범위: indexStart/indexCount와 재질 슬롯.
  • 카메라 위치: 뷰 역행렬로 구해도 되지만 명시합니다.
  • 텍스처 바이트: Scene::FindImage가 하던 씬 임베드 이미지를 어떻게 줄지 정합니다. FBX 임베디드 텍스처가 미완료 항목이므로 같이 설계합니다. 안은 둘입니다: (a) 파일 경로만 전달하고 렌더가 로드, (b) 엔진이 디코딩한 이미지 데이터를 공유 불변 객체로 전달.

CollectRenderFrame은 엔진 담당 영역이므로 요구 사항 목록을 전달합니다. 수명 규칙은 문서 그대로입니다: 객체 삭제 시 공유 리소스는 유지(P09), 진행 중 GPU 사용의 안전한 해제 규격은 미합의(P10)이므로 이 포팅에서 함께 정합니다.

6.2 메시 데이터와 GPU 캐시

  • MeshVertex에 tangent(float4)를 추가합니다. Assimp의 aiProcess_CalcTangentSpace로 생성하고, 못 구하면 UV 기반으로 계산합니다. Sherlock 노멀맵 셰이더가 탄젠트 없이는 동작하지 않습니다.
  • 정점 색은 Sherlock이 RGBA, Nereides가 RGB입니다. 스킨드 포맷을 새로 정의할 때 하나로 정합니다.
  • 인덱스는 정점이 65,535개 이하면 16비트, 아니면 32비트입니다(GetOrCreateGpuMesh, 1285). MeshData::indices가 unsigned로 고정이어도 GPU 업로드 시 변환하면 됩니다.
  • DrawItem과 미리보기 카메라가 원시 포인터를 듭니다. 호출이 끝날 때까지만 유효하다고 주석에 명시합니다.

캐시 키가 가장 위험합니다. Sherlock은 Mesh*/Material* 포인터를 키로 쓰고(Renderer.h:274-276), Scene이 unique_ptr로 소유하므로 안정적이었습니다. Nereides는 매 프레임 shared_ptr이 오가고 마지막 참조가 사라지면 해제되므로, 주소가 재사용되면 옛 GPU 버퍼를 돌려주는 사고가 납니다. 기존 Nereides 방식(weak_ptr + expired() 확인 후 정리)을 유지하고 재질도 같은 방식으로 합니다. 변경은 기존 객체 수정이 아니라 새 불변 데이터로 교체합니다.

6.3 스키닝 새로 구현

대상변경 내용
정점 포맷VertexTypes.h에 포맷이 하나뿐입니다. 스킨드 포맷(Position, Color, Normal, UV, Tangent, BLENDINDICES uint4, BLENDWEIGHT float4)을 추가하고 정적 포맷은 그대로 둡니다. sizeof(VERTEX)(1274)와 stride(1277)를 포맷별로 쓰는지 확인합니다.
상수버퍼오브젝트 버퍼(ShaderConstants.h:71-75, b1, 128B)는 world와 worldInvTranspose만 있습니다. 뼈 행렬 128개(8KB)를 같은 버퍼에 넣지 말고 별도 슬롯(예: b4)을 만듭니다. 새 슬롯이면 objectLayout(Renderer.cpp:100-103)과 ValidateBindings의 declared[](607-626)에 선언합니다. 크기 검사(71, 528-535)는 sizeof를 쓰므로 자동 반영됩니다.
HLSLCommon.hlsli:57-61 cbuffer를 C++ 구조체와 같은 바이트로 맞추고, 메인 VS와 그림자 VS(ShadowVertexShader.hlsl:13-14) 둘 다에 스키닝을 넣습니다. 그림자 PSO(1409-1416)는 같은 정점 레이아웃을 씁니다.
업로드UploadObjectConstants는 그림자 패스(1018)와 메인 패스(1137)에서 서브메시마다 호출됩니다. 뼈 데이터의 출처는 RenderFrame의 DrawItem::bones이므로 두 패스가 같은 데이터를 읽게 합니다. 뼈 행렬은 mesh inverse bind × animated global, 최대 127개 + fallback 1개입니다.
예외 처리weights 합이 0이면 스키닝을 건너뜁니다(현재 Nereides 셰이더 동작). 노멀·탄젠트도 스킨 행렬로 변환하며, 비균일 스케일이 가능한지 확인합니다.

6.4 행렬 업로드 규약 놓치기 쉬움

두 엔진이 같은 row-vector 규약이지만 GPU로 올리는 방식이 다릅니다.

  • Sherlock: C++에서 행렬을 전치해서 올리고(UploadObjectConstants, 969-979), HLSL은 기본 column_major cbuffer로 받아 mul(v, M)을 씁니다. 역전치 자리에는 W⁻¹을 넣습니다.
  • Nereides: 전치 없이 올리고 HLSL에 row_major를 선언합니다. WVP는 CPU에서 world × view × projection을 곱해서 보냅니다.

옮기는 렌더러는 Sherlock 셰이더를 그대로 쓰므로 Sherlock 방식(업로드 시 전치)을 따릅니다. RenderFrame의 행렬과 뼈 행렬은 Nereides 규약(전치 안 된 XMFLOAT4X4)으로 오므로 렌더러 안에서 올릴 때 전치합니다. 뼈 행렬을 row_major로 선언하거나 전치해서 올리는 둘 중 하나로 통일하고, 한 모델을 눈으로 확인합니다. 어긋나면 뼈가 뒤틀리거나 모델이 뒤집혀 보입니다.

6.5 장치·스왑체인 소유권

  • Application이 RHI::Device를 만들고 렌더러가 핸들만 다루게 바꿉니다. D3D11Renderer는 대체 대상입니다.
  • UI 패스 책임: Sherlock Render()는 UI 패스를 호출하지 않습니다. 호스트가 BeginUIPass/EndUIPass(1224-1253)를 불러야 백버퍼가 Present 상태로 돌아갑니다. Nereides의 SetOverlay 콜백 자리가 여기에 해당합니다.
  • 에디터가 쓰는 SceneView()는 SetSceneTarget/GetSceneTexture(1431-1473)로 대체합니다. 이 함수들은 텍스처만 만들어 분리가 쉽습니다. 오프스크린 배경 clear(1233-1239)는 에디터 전용입니다.
  • ImGui DX11 초기화에 필요한 ID3D11Device*/ID3D11DeviceContext*는 D3D11 백엔드에서 꺼내는 통로를 하나 만듭니다. 추상화가 새는 곳이므로 한곳에 모아 주석으로 남깁니다.
  • RequestCapture, 픽셀 해시 검증(--smoke-test 등), Resize를 새 경로로 옮깁니다. 최소화(0 크기) 처리 규격은 문서에 미정(R04)입니다.
  • 소멸자가 Shutdown을 부르므로(48-51) 디바이스가 먼저 죽으면 정의되지 않은 동작입니다. 해제 순서를 Application에서 명시합니다.

6.6 셰이더와 경로

  • Sherlock Shaders/의 Basic VS/PS, Shadow VS, Skybox VS/PS, Common.hlsli와 Graphics/ShaderConstants.h(CPU/HLSL 상수 구조체)를 한 세트로 옮깁니다.
  • 컴파일은 RHI/DXBC/ShaderCompiler(D3DCompile + 리플렉션)에 묶여 있습니다. 난이도가 가장 높으므로 RHI와 함께 옮기고 따로 떼어내려 하지 않습니다. LoadOrCompile은 .cso가 있고 소스보다 새로우면 그것을 씁니다(ShaderCompiler.cpp:131-167).
  • MeshShaders.h 문자열 방식은 버리고 파일 방식으로 통일합니다.
  • 핫리로드는 _DEBUG에서만 동작하고 0.5초 폴링, 감시 파일 6개(Renderer.cpp:588-589)입니다. 폴링 간격이 벽시계가 아니라 totalTime 기준이므로 일시정지 중에는 리로드가 안 됩니다. 이식 시 이 시간 입력을 RenderFrame::time으로 받을지 정합니다.
  • 경로: Core/Paths의 GetShaderSourcePath가 엔진 루트(engine.ini 마커 또는 exe 기준 상대 경로)의 Shaders\를 찾습니다. Nereides는 실행 파일 위치에서 프로젝트 루트 또는 배포 data 폴더를 찾는 규칙이 있으므로 그 규칙으로 대체합니다. 배포 패키지(scripts/package.ps1)에 셰이더를 복사하는 규칙도 추가합니다.

6.7 텍스처와 환경

  • TextureLoader를 통째로 가져오고 directxtex를 vcpkg에 추가합니다.
  • 재질 텍스처 이름 규칙(asset:, builtin:, Assets/Textures/ 기준)을 Nereides의 assets/ 구조에 맞춥니다.
  • 텍스처 캐시는 이름 + 색공간이 키이고 씬 범위가 아닙니다(Renderer.h:240). 구역 교체 시 InvalidateScene 같은 일괄 해제 지점이 필요합니다. 구역 교체는 암전 중 동기 로딩 후 이전 리소스를 해제하는 방식입니다(기술검토서 §145).
  • 환경(IBL) 에셋은 HDR 큐브맵입니다. 에셋은 드라이브로 공유하므로 필요한 파일 목록을 팀에 알립니다.

6.8 하드코딩된 가정

  • 그림자 중심이 (0, 2, 0)에 고정(Renderer.cpp:839), 직교 크기 60, 맵 2048². 보스전 구역 크기에 맞춰 조정할 수 있어야 합니다.
  • 광원 8개 제한이 조용히 잘립니다(881). 로그를 남깁니다.
  • 스카이박스는 environment.skybox가 비어 있지 않으면 그리고, 로드 실패 시에도 검은 큐브로 그립니다(1144).
  • 한 프레임에 Render를 두 번 부르면 통계가 리셋되고(859) 재질 상수 업로드는 m_frameNumber 기준 프레임당 한 번입니다(1377).
  • 드로우마다 객체 상수와 b0를 다시 올리는 방식은 RHI가 Discard/업로드 링을 보장한다고 가정합니다(971-972, 1165). RHI를 옮길 때 이 보장을 유지합니다.
  • 프레임 셋은 환경이 바뀌면 즉시 Destroy합니다(283). 지연 삭제를 가정하므로 D3D11에서만 안전합니다.

6.9 빌드와 의존성

  • Sherlock 렌더러 소스는 src/Graphics/와 src/RHI/에 직접 넣습니다. 라이브러리 분리는 하지 않습니다.
  • 새 패키지: directxtex(dx11 기능). cgltf는 glTF 로딩을 옮길 때만 필요하며 FBX 경로만 쓰면 불필요합니다. 팀 규칙상 FBX가 기본이고 로더는 Assimp 우선 검증입니다.
  • ImGui 기능은 Nereides가 dx11-binding, win32-binding입니다. Sherlock의 docking-experimental은 렌더 포팅에 필수가 아니므로 에디터 담당과 협의 전에는 추가하지 않습니다.
  • D3D12 백엔드(RHI/D3D12)는 제외합니다. Device.h가 D3D12 헤더를 끌고 오지 않는지 확인합니다.
  • 새 파일은 .vcxproj/.filters에 등록합니다(CRLF 유지). scripts/sync-project.ps1이 이 일을 한다면 그것을 씁니다. 이 파일도 사전 조율 대상입니다.
  • Dependencies.props의 링크 목록에 directxtex.lib를 추가합니다.
  • Nereides vcpkg baseline(06d00ff…)은 유지합니다. 패키지 추가 후 scripts/setup-dependencies.ps1로 설치가 되는지 확인합니다.
