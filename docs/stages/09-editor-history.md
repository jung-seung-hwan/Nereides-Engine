# 09 편집 이력과 장면 복구 기반

2026-10-06. 에디터 완료 기준을 “팀원이 모델을 찾고 배치하고 수정·복구·저장할 수 있다”로 확장한다. 이 단계는 복구·선택의 기반이며 실제 화면과 조작은 10단계에서 연결한다.

## 목적과 결정

수정 취소는 위치 이동만이 아니라 객체 추가·삭제, 부모 관계와 편집 가능한 속성까지 복구해야 한다. SceneIO의 파일 저장과 동일한 검증 경로로 장면을 메모리 문자열에 기록한다. 런타임 객체 ID는 복구 때 새로 만들되, 저장 데이터의 ID는 객체 순서에 따른 번호로 정규화한다. 따라서 같은 장면을 복구했을 때 ID가 달라져도 수정된 장면으로 오인하지 않는다.

EditHistory는 최대 64회의 Undo와 32 MiB의 이력 문자열을 보관한다. 최신 상태 하나는 유지하므로 큰 장면 하나가 제한보다 크면 예외다. Undo 이후 새로운 수정을 하면 이전 Redo 경로를 없앤다. 저장 지점을 별도로 기록해 저장 당시 상태로 되돌아가면 변경 표시도 해제한다. 모델 파일 자체나 재생 중 애니메이션·이벤트는 이력에 복사하지 않는다.

Undo 대상은 먼저 새 Scene으로 읽어 검증한 뒤 교체한다. 외부 모델이 사라지는 등 복구에 실패하면 현재 장면과 이력 위치를 유지한다. 객체 포인터와 ID는 교체 뒤 다시 얻어야 한다. 콘텐츠의 복잡한 사용자 컴포넌트에는 기존과 마찬가지로 명시적인 직렬화 등록이 필요하다.

## 파일 읽기 순서

1. src/Data/SceneIO.h, src/Data/SceneIO.cpp: Encode/Decode와 파일 Save/Load의 공통 경로.
2. src/Editor/EditHistory.h: 저장 지점, Undo/Redo 분기, 이력 제한.
3. src/Editor/EditorGeometry.h: 부모 변환과 현재 스키닝 포즈를 반영한 바운딩 박스, 화면 선택용 Ray.
4. src/Tests/EngineTests.cpp: TestEditorHistory의 삭제된 부모·자식 복구와 저장 지점 검증.

모델 경로는 UTF-8로 직렬화하고 파일 시스템 접근 시 Windows 경로로 변환한다. 한글 파일 이름을 가진 모델도 같은 경로를 따른다.

## 검증

--engine-tests에서 장면 왕복 후 동일한 직렬화 결과, 부모·자식 동시 삭제 복구, Undo 후 새 분기, 저장 상태 복귀, 64회 이력 제한, 부모 변환을 반영한 선택 범위와 빈 공간 선택을 확인한다. 기존 저장 실패 시 이전 파일 보존 검사도 유지한다.

2026-10-06 Debug 검증을 통과했다. 실제 에디터 버튼·키 입력과 Release 검증 결과는 10단계 문서에 기록한다.

## 범위

에디터용 장면 복구다. 전투 중 체크포인트 저장이나 게임 전체 상태 복원을 구현한 것은 아니다. 모델·텍스처 원본을 씬 파일에 포함하지 않으며, 공유할 때 원본 파일과 상대 경로도 함께 유지해야 한다.
