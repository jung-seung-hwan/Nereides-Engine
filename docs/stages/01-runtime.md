# 01 실행 입력 시간 로그

목적은 콘텐츠가 창 메시지와 DX11 코드를 몰라도 입력과 시간을 사용할 수 있게 하는 것이다. 기존 삼각형 GPU 검증은 유지한다.

## 읽는 순서

1. `src/Main.cpp`: 명령 선택과 Application 시작만 담당한다.
2. `src/Core/Application.cpp`: 입력 초기화 → 창 메시지 → 시간 → 렌더 호출. 멤버 소유 순서로 렌더가 창보다 먼저 종료된다.
3. `src/Core/Input.h`: 눌림/유지/해제를 구분한다. 한 프레임 안의 눌림과 해제도 보존한다. 전환·포커스 상실 시 이전 행동을 제거한다.
4. `src/Platform/Win32Window.cpp`: Win32 키/마우스 메시지를 Input에 전달한다. 상대 마우스 이동은 Raw Input, Alt+F4는 기본 창 처리로 전달한다.
5. `src/Core/Time.h`: 실시간, 배율이 적용되는 전투 시간, 배율 없는 탈출 시간, 별도 연출 시간을 제공한다.
6. `src/Tests/EngineTests.cpp`: 창 없이 입력/시간 경계를 재현한다. 실패는 1, 성공은 0을 반환한다. 로그는 작업 디렉터리의 `logs/engine.log`에 남는다.

## 실행과 확인

솔루션에서 F5로 실행한다. 제목에 전투·탈출 시간을 표시하고 Esc로 일시정지/복구한다. 키를 누른 채 Alt-Tab 후 복귀해 이전 행동이 재시작되지 않는지 확인한다. 최소화 대기 시간은 복구 프레임에 누적하지 않는다.

`powershell -ExecutionPolicy Bypass -File scripts/verify.ps1`은 VS2022를 찾아 Debug/Release 빌드, `--engine-tests`, GPU 픽셀 검사 `--smoke-test`를 수행한다. 각 실행에 20초 제한이 있고 실패 시 스크립트가 실패한다. 셸 실행 정책 변경은 프로세스에만 적용된다.

## 계약과 남은 일

입력은 기존 README의 DirectXTK 계획과 달리 이번 단계에서 Win32 백엔드로 구현했다. 라이브러리 형식을 콘텐츠에 노출하지 않는 API를 먼저 제공하기 위한 선택이며 DirectXTK를 설치하거나 연결했다고 주장하지 않는다. 키 코드는 현재 Windows 가상 키 값, 시간은 초 단위 double이다.

일시정지 중 연출은 기본 정지하되 `pausePresentation`으로 변경한다. 원문 미정 정책을 최종 합의로 취급하지 않는다. `combatStopped`는 구역 진입 후 전환 구간에 사용한다. 탈출 중 전투가 계속되는 구간에는 켜지 않는다. Hit Stop은 아직 없다.

렌더/창 초기화 실패의 기존 진단 창은 유지한다. 로그는 단순 파일/VS 출력이며 에디터 로그 패널은 후속 단계다. 자동 테스트는 입력 상태 API를 검증하며 실제 OS 키보드·다중 모니터 조작의 완전한 검증을 의미하지 않는다.

## 검증 결과

2026-10-06 Debug/Release x64 빌드 성공. 두 구성의 입력·시간 경계 테스트와 기존 GPU 배경/삼각형 픽셀 검사 모두 exit 0. 빌드 출력 경고 없음.
