# 바이브코딩 공용 규칙

여러 프로젝트에서 일관되게 작업하기 위한 기본 골조입니다. 사용자와 AI가 함께 따르는 작업 방향을 정하며, 기술·도구·파일 구조·제작 규격 등 세부 사항은 각 프로젝트에 맞게 정합니다.

## 사용 방법

프로젝트에서 이 파일을 지정하고 **“이 MD 파일대로 작업 시작하자”**라고 요청하면 됩니다.

이 시작 요청에는 **기존 상태 확인 → 필요한 질문 → 답변에 따른 작업별 세션 구성·생성 → 최소 문서 구조 마련 → 합의된 첫 작업 시작**을 포함합니다. 세션 생성 요청을 따로 반복할 필요는 없습니다. AI는 아래 규칙에 따라 부족한 정보만 묻고, 답변으로 범위가 정해지면 진행합니다.

이미 준비된 프로젝트에서는 기존 문서와 세션을 활용하고 필요한 부분만 보완합니다. 파일을 읽거나 수정해 달라는 요청만으로 이 시작 절차를 실행하지는 않습니다.

## 1. 작업 단위로 세션을 나눈다

- 한 세션은 하나의 주목표를 중심으로 진행합니다. 해당 목표를 위한 논의·제작·구현·수정·검증은 같은 세션에서 이어갑니다.
- 독립적인 다른 작업을 시작하거나, 맥락이 너무 쌓여 현재 목표와 결정 사항을 파악하기 어려워지면 정리한 뒤 새 세션으로 넘깁니다. 대화 횟수나 시간만으로 일률적으로 나누지 않습니다.
- 세션 이름은 `[프로젝트] 작업 목적 · 01` 형식을 기본으로 합니다. 같은 작업을 다음 세션에서 이어가면 순번을 올립니다.
- 예: `[프로젝트명] 시작 화면 제작 · 01` → `[프로젝트명] 시작 화면 제작 · 02`

### 처음 세션을 구성할 때 묻는 질문

먼저 기존 프로젝트와 대화에서 알 수 있는 내용을 확인하고, 아래 질문 중 답이 없는 항목만 사용자에게 짧게 묻습니다. 사용자가 세션 개수나 기술적인 작업 분류를 직접 정할 필요는 없습니다.

1. **이번에 어떤 결과를 만들고 싶나요?** 누구를 위한 것인지, 무엇이 되면 첫 목표를 달성한 것인지 알려주세요.
2. **먼저 끝내고 싶은 일과 그다음 할 일은 무엇인가요?** 정해진 순서나 일정이 없다면 AI가 작업 순서를 제안합니다.
3. **이미 있는 자료나 꼭 유지해야 할 기준이 있나요?** 기존 코드·문서·디자인·참조 자료와, 반복해서 생성할 이미지·글 등의 유무를 확인합니다.

답변을 바탕으로 AI가 세션별 **이름 / 목표와 완료 조건 / 먼저 필요한 작업 / 첫 행동**을 짧게 정리합니다.

- 독립적으로 완료할 수 있는 목표를 기준으로 나눕니다. 같은 목표의 조사·구현·검증을 기계적으로 다른 세션으로 쪼개지 않습니다.
- 지금 시작할 작업과 가까운 후속 작업만 구성합니다. 먼 미래의 작업이나 목표 없는 분야별 빈 세션은 만들지 않습니다. 작은 작업은 현재 세션 하나로 충분할 수 있습니다.
- 반복 생성이 필요하면 해당 제작 세션의 첫 단계에 기준 프롬프트와 참조 자료 확정을 포함합니다.
- 기존 세션이 같은 목표를 맡고 있으면 활용합니다. 같은 파일을 수정하거나 앞 작업의 결과가 필요한 세션은 순서를 정합니다.

사용자가 “이 MD 파일대로 작업 시작하자”라고 요청하거나 세션 구성과 생성을 직접 요청한 경우, 답변으로 범위가 정해지면 필요한 세션을 실제로 만들고 이름과 연결을 알려줍니다. 구성 제안만 요청한 경우에는 제안까지만 합니다. 생성 기능이 없는 환경에서는 세션별 시작 메시지를 제공합니다.

각 새 세션의 첫 메시지에는 공용 규칙·프로젝트 안내의 위치, 해당 목표와 완료 조건, 참조 자료, 첫 행동을 넣습니다. 후속 작업용으로 미리 만든 세션은 선행 조건을 확인하고 기다리도록 명시하며, 세션 생성 자체를 모든 작업의 동시 실행으로 취급하지 않습니다.

사용자는 다음과 같이 요청하면 됩니다.

> 이 MD 파일대로 작업 시작하자.

### 다음 세션으로 넘기는 기준과 방법

같은 작업이 남아 있을 때 다음 상황을 인계 시점으로 판단합니다.

- 대화에 여러 수정 과정과 결정이 쌓여 현재 기준을 찾기 어려워졌을 때
- 이미 확정한 조건을 놓치거나 같은 설명·조사를 반복해 작업의 일관성이 떨어질 때
- 한 단계가 정리되어, 남은 목표와 다음 행동을 명확하게 넘길 수 있을 때
- 사용자가 다음 세션에서 이어가기를 요청했을 때

대화 횟수나 시간은 참고만 합니다. 인계가 유용해 보이면 이유를 짧게 알리고 제안합니다. 사용자가 후속 세션 생성을 요청하면 아래 절차를 실행하며, 규칙 문서에 인계 절차를 추가하는 요청만으로 새 세션을 만들지는 않습니다.

1. **현재 상태를 정리합니다.** 진행 중인 수정·생성·검사의 상태를 확인하고, 완료·미완료·사용자 결정 대기를 구별해 기록합니다. 인계를 위해 미완료 작업을 완료로 표시하거나 임의로 커밋하지 않습니다.
2. **인계 내용을 남깁니다.** 기존 진행 문서의 해당 작업을 갱신합니다. 목표와 완료 조건, 확정 결정, 기준 프롬프트·참조 자료의 위치와 버전, 주요 변경, 실제 검증, 남은 일, 다음 첫 행동을 필요한 만큼 기록합니다. 작업 폴더·브랜치·미커밋 변경과 다른 세션의 진행 작업도 관련이 있으면 명시합니다.
3. **후속 세션을 만듭니다.** 같은 프로젝트와 작업 위치를 기본으로 하고, `[프로젝트] 같은 작업 목적 · 다음 순번`으로 만듭니다. 이미 이어받는 세션이 있는지 확인해 중복 생성을 피합니다. 다른 독립 목표라면 새 작업명과 `01`을 사용합니다.
4. **첫 메시지로 인계합니다.** 공용 규칙과 프로젝트 안내·인계 기록의 정확한 위치, 앞 세션의 이름 또는 식별자, 남은 목표와 첫 행동을 전달합니다. 새 세션은 필요한 기록과 실제 파일 상태를 확인한 뒤 합의된 작업을 이어갑니다. 사용자 결정 대기 사항은 그대로 유지합니다.
5. **작업 담당을 넘깁니다.** 새 세션 생성 결과를 확인하고 사용자에게 연결을 제공합니다. 기존 세션은 같은 작업의 파일 수정을 멈추고 인계 기록으로 남습니다. 자동으로 삭제하거나 보관 처리하지 않습니다.

세션 생성 기능이 없는 환경에서는 인계 기록과 새 세션에 붙여 넣을 첫 메시지를 제공합니다. 실제 생성 여부를 분명하게 알립니다.

사용자는 다음과 같이 요청하면 됩니다.

> 이 공용 규칙대로 현재 작업을 인계하고, 이어서 작업할 다음 세션을 만들어줘.

## 2. 반복 생성에는 기준 프롬프트를 둔다

- 이미지·원고·음원·영상 등 반복 제작이 필요한 작업은 용도별 기준 프롬프트와 참조 자료를 먼저 정하고 저장합니다.
- 이후 생성은 그 기준을 사용하고, 이번 작업에 필요한 개별 입력만 바꿉니다. 유지할 요소와 바꿀 수 있는 요소가 드러나도록 작성합니다.
- 결과가 만족스럽지 않으면 원인을 살펴 개별 입력 또는 공통 기준을 개선합니다. 매번 기준을 임의로 새로 쓰거나 근거 없이 같은 생성을 반복하지 않습니다.
- 기준 자체를 바꿀 때는 변경 내용이나 버전을 간단히 남깁니다. 결과물에서 사용한 기준을 다시 찾을 수 있게 합니다.
- 고정 프롬프트는 일관성을 위한 출발점이며, 결과물은 작업 목적에 맞게 별도로 확인합니다.

## 3. 확정된 기준을 이어간다

- 확정한 결정, 승인된 기준 자료, 현재 작업 상태는 대화에만 두지 않고 프로젝트 문서에 간단히 남깁니다. 제안과 확정 사항은 구별합니다.
- 다음 세션은 기존 기록과 실제 파일 상태를 확인하고 이어갑니다. 이미 정한 내용을 이유 없이 다시 결정하거나 완료한 조사를 반복하지 않습니다.
- 기존 작업과 사용자 수정사항을 존중합니다. 기준을 바꿀 필요가 있으면 바뀌는 내용과 이유를 분명히 합니다.

## 4. 목적에 필요한 만큼 작업하고 확인한다

- 시작할 때 이번 작업의 목표와 완료 조건을 짧게 맞춥니다.
- 합의한 범위 안에서는 필요한 작업을 이어가고, 의도나 범위가 크게 달라지는 결정은 사용자와 맞춥니다.
- 관련된 자료부터 확인하고, 요청한 결과와 변경에 맞는 검증에 집중합니다. 불필요한 조사·재생성·문서화를 늘리지 않습니다.
- 마칠 때는 바뀐 내용, 실제 확인한 결과, 남은 일을 간단히 알립니다. 구현한 것과 검증한 것을 구별합니다.

## 5. 공용 원칙은 가볍게 유지한다

- 공용 규칙에는 여러 프로젝트에 반복해서 필요한 방향만 둡니다. 프로젝트별 실행 방법, 기술 제약, 제작 규격은 해당 프로젝트 문서에 둡니다.
- 현재 기준 문서를 갱신하며 사용합니다. 같은 내용을 여러 문서에 반복하거나 일회성 예외를 공용 규칙으로 계속 추가하지 않습니다.
- 규칙은 실제 작업에 도움이 되는 만큼 보완합니다. 기록과 절차 자체가 작업의 목적이 되지 않도록 합니다.

## 프로젝트 최초 시작

새 프로젝트에서 이 문서를 작업 기준으로 전달받으면, 아래 흐름에 따라 최소한의 작업 골격을 마련하고 첫 작업으로 이어갑니다.

1. **목적과 첫 작업을 정합니다.** 사용자의 요청에서 프로젝트의 목적과 첫 작업의 목표·완료 조건을 파악합니다. 이미 정해진 내용은 활용하고, 시작에 필요한 정보가 빠져 있을 때만 질문합니다.
2. **기존 구조를 확인합니다.** 기존 파일·문서·작업 규칙이 있으면 그 구조를 활용합니다. 새 프로젝트라면 현재 필요한 최소한의 구조부터 만듭니다.
3. **기준과 상태를 기록할 자리를 마련합니다.** 프로젝트 목적과 확정된 기준을 담을 안내, 현재 목표와 다음 행동을 담을 진행 상태 기록을 준비합니다. 작은 프로젝트에서는 한 문서의 항목으로 합쳐도 됩니다. 반복 생성이 필요할 때는 기준 프롬프트와 참조 자료를 보관할 자리도 마련합니다.
4. **다음 세션에서 찾을 수 있게 연결합니다.** 프로젝트의 시작 안내 문서에 이 공용 규칙과 관련 기록의 위치를 적습니다. 파일명과 폴더는 프로젝트에 맞게 정하고, 확정되지 않은 기술이나 세부 규칙은 미리 정하지 않습니다.
5. **세션을 구성하고 첫 작업을 시작합니다.** ‘처음 세션을 구성할 때 묻는 질문’에 따라 필요한 답을 확인하고 작업을 나눕니다. 이 문서대로 작업을 시작하라는 요청에 포함된 세션 구성·생성을 수행한 뒤, 합의된 첫 작업을 진행합니다. 준비 문서를 만드는 것으로 작업을 끝내지 않습니다.

## 기본 작업 흐름

**시작:** 기존 기준과 현재 상태를 확인하고, 이번 목표와 완료 조건을 맞춥니다.

**진행:** 기준에 따라 작업하고 필요한 만큼 검증합니다. 확정된 변경 사항을 기록합니다.

**마무리·인계:** 결과와 남은 일을 정리합니다. 다음 세션이 필요하면 아래 항목을 기존 진행 문서나 인계 메시지에 짧게 남깁니다. 매번 별도 문서를 만들 필요는 없습니다.

```text
이번 목표:
확정한 기준과 참조 문서:
현재 상태와 주요 변경:
확인한 결과와 남은 일:
다음에 할 일:
```

새 프로젝트에서는 이 문서를 공용 기준으로 사용하고, 프로젝트별 안내와 진행 상태 기록을 연결해 시작합니다. 문서의 위치와 도구는 프로젝트에 맞게 선택합니다.
