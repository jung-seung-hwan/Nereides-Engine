각 단계는 작은 검증 단위로 추가 커밋할 수 있다. 원문 미정 사항의 구현 선택은 해당 단계 문서에서 임시 계약으로 표시한다. 렌더·플레이어·보스 담당의 실제 산출물이 필요한 검증은 대체 예제와 구분하고, 기반 제공을 게임 완성으로 표기하지 않는다.

## 따라가는 방법

1. 단계 문서의 목적과 실행 결과를 읽는다.
2. 해당 커밋에서 실행해 보고 조작과 검증 명령을 확인한다.
3. 문서의 파일 순서대로 읽는다. 각 파일에서 소유하는 데이터와 다음 호출만 먼저 따라간다.
4. 임시 결정·제약과 다음 단계의 연결을 확인한다.

단계 문서에는 목적, 포함 범위, 파일 읽기 순서, 실행/검증, 실제 결과, 미완료 항목을 기록한다. 커밋은 `git log --oneline --reverse 54f096f..HEAD`로 찾는다. 이전 단계 실행은 현재 작업 트리를 되돌리지 말고 별도 체크아웃에서 수행한다.

## 구현 기본 계약

- Windows / VS2022 v143 / C++20 / DX11을 유지한다.
- 단일 스레드 갱신부터 시작한다. 입력 → 행동 → 변환/재생 → 후보 → 콘텐츠 결과 → 렌더 입력 순으로 확장한다.
- 내부 길이는 미터, 회전은 라디안, 시간은 초를 기본 제안으로 사용한다. DirectXMath 기반 왼손 좌표(+Y 위, +Z 앞), 행 벡터·local × parent를 채택해 예제에서 검증한다. 렌더 포팅 담당과 연결 시 확인한다.
- 엔진은 수명과 사실을 제공하고 게임 규칙은 콘텐츠에 둔다. 임시 도형·검증용 행동을 게임 구현으로 취급하지 않는다.
- 실측 전 전 단계 완료일을 약속하지 않는다. 11월 23일 시연·12월 16일 내부 완료의 합격 범위는 범위 문서를 따른다.
