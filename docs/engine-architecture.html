02 / FRAME & FIXED TICK

한 프레임에서 실제로 실행되는 순서

① 입력 수집 — Input.BeginFrame → Win32 메시지 처리
↓
② 에디터·실행 상태 처리 — UI 편집, Play/Stop, 일시정지·전환·포커스 확인
↓
③ 프레임 시간 진행 — Time.AdvanceFrame, 연출 시간 진행, 고정 시간 누적

④ 고정 tick 블록 전체를 0~8회 반복 · 기본 50Hz / 0.02초

Input.ConsumeTick → Time.AdvanceTick
↓
Scene.FixedUpdate → 초기화 확인 → Logic → Animation → Late
↓
CollisionWorld.Step → 충돌 후보 목록
↓
ResolveContacts → 현재 Enter 로그 / 게임 판정 연결 지점
↓
Events.Dispatch → Scene.Flush → 알림 전달 후 실제 삭제
⑤ Scene.Update — Play 중 프레임마다 한 번. 초기화 확인 → Logic → Animation → Late → 정리
↓
⑥ 렌더 데이터 수집 — CollectRenderFrame, 에디터 뷰 카메라 적용
↓
⑦ 화면 출력 — D3D11Renderer.RenderScene → 에디터 오버레이 → Present
조건동작
Edit 모드게임용 Update/FixedUpdate는 호출하지 않는다. 편집·렌더링은 수행한다.
Play 중 일시정지·전환고정 전투 갱신은 중단한다. 프레임 Update는 호출할 수 있으므로 적절한 시계 delta를 사용한다.
긴 프레임최대 8 tick을 따라잡고 초과 시간은 버린다. 소수 잔여 시간은 유지한다.
씬 교체·재개누적 tick과 이전 입력 등을 정리해 정지 중 입력·시간을 다시 실행하지 않도록 한다.

50Hz는 화면 FPS와 다르다. FixedUpdate와 Update 모두 내부에 Logic/Animation/Late 단계가 있고, LateUpdate라는 별도 함수는 없다. 렌더 보간은 아직 없다.

실제 루프: Application.cpp · 입력: Input.h · 시간: Time.h

03 / OBJECT & COMPONENT

객체 구성과 라이프사이클

Scene.Create
→
Object / ID·Transform·부모
→
Add<T> / Component 소유

콘텐츠는 Scene에서 객체를 생성하고 위치·회전·크기를 설정한다. 이동이 필요하면 MoveComponent를 붙이고, 모델이 필요하면 ModelComponent를 붙인다. Scene이 객체와 입력·시간을 컴포넌트 콜백에 전달한다. Camera는 Component가 아닌 별도 설정 구조체이며 카메라 객체의 변환과 함께 사용한다.

BeginPlay
→
전체 Awake
→
활성 OnEnable
→
최초 Start
단계담당할 작업 / 현재 규칙
Awake참조 확보·내부 준비. 비활성이어도 현재 초기화 목록에서 한 번 호출한다.
OnEnable / Start활성 등록 후 최초 행동 시작. 재활성화 시 OnEnable은 반복되지만 Start는 인스턴스마다 한 번이다.
Update / FixedUpdate활성이고 Start를 마친 대상만 호출한다. 단계 내부는 객체 생성 → 컴포넌트 추가 순서다.
실행 중 Add인스턴스는 즉시 생성된다. 콜백 참여는 다음 갱신 경계에서 초기화 후 시작한다.
SetEnabled(false)실행 대상에서 제외하고 안전한 경계에서 OnDisable을 처리한다. 부모가 비활성이면 자식도 실행되지 않는다.
Remove / Destroy삭제 예약 후 Flush에서 필요한 OnDisable·OnDestroy를 호출하고 메모리를 해제한다. Awake 전 삭제는 OnDestroy를 호출하지 않는다.
EndPlay / 에디터 StopEndPlay가 전체 비활성화·파괴를 처리한다. 에디터는 Play 전 스냅샷을 별도로 복원한다.

단계 기반 초기화는 구현됐다. 숫자 우선순위나 컴포넌트 의존성 정렬은 아직 없다. A.Start에서 B.Awake 완료를 활용할 수 있지만 B.Start 완료까지 가정하면 안 된다. 여기서 전체는 해당 경계의 초기화 목록이다.

등록 정보에는 영구 타입 이름, 표시 이름, 생성 함수, 속성 이름·자료형·기본값·범위·읽기/쓰기 함수가 있다. 에디터는 이 정보로 UI를 만들고 SceneIO는 같은 정보로 값을 저장한다. C++ 클래스의 모든 멤버를 자동으로 탐색하는 기능은 아니다.

MoveComponent 등록 예시

result.Register(
    DescribeComponent<MoveComponent>(
        "move", "Move Component", {
            Property("speed", "Move speed",
                     &MoveComponent::speed, 0, 1000)
        }));

ComponentRegistry.cpp의 기본 등록 예시. 별도 콘텐츠 타입은 편집·로드 전에 ComponentTypes().Register(...)로 등록한다. 기본 생성자가 필요하며 생성자는 외부 실행 작업을 하지 않도록 작성한다.

유지되는 씬 파일 형식

{
  "type": "move",
  "speed": 3.0,
  "enabled": true
}

기존 version 1의 move/speed 형식을 유지한다. 등록 이후 추가된 필드가 과거 파일에 없으면 등록 기본값으로 복원한다. 파일 타입 이름 변경에는 별도의 마이그레이션이 필요하다.

현재 지원구체적 범위
속성 자료형float, int, unsigned, bool, DirectX::XMFLOAT3 및 이름을 등록한 열거형. 숫자는 유한성·범위를 검사하고 정수는 소수와 오버플로를 거부한다.
기본 등록 타입Move, Collider, Mesh(Cube), Model, Parameters. 모두 추가·삭제·활성 전환 가능. 같은 타입 중복 추가를 막는다.
편집 기록기존 SceneIO 스냅샷을 사용하므로 등록 컴포넌트도 Undo/Redo·저장·Stop 복원에 참여한다.
오류 처리미등록 타입, 중복 등록, 중복 컴포넌트, 잘못된 필드 값은 오류로 처리한다. 불러오기는 별도 Scene을 구성한 뒤 성공 시 교체한다.
편집·저장 경계Collider는 형태·크기·오프셋·layer/mask·Trigger를 공통 속성으로 처리한다. cube/model/parameters는 리소스·동적 맵의 전용 직렬화를 유지한다. Mesh 색상과 Parameters 항목 편집은 공통 패널 안에 제공한다. Model 추가는 파일 선택 후 기존 객체에 부착하며 실패·취소 시 변경하지 않는다. Assets의 모델 배치도 유지한다.

런타임 포인터, 이벤트 구독 번호, Start 호출 여부는 등록·저장하지 않는다. 현재 공통 속성에 일반 문자열·객체 참조·범용 리소스 속성·배열·중첩 구조체는 포함하지 않았다. 모델 파일 선택은 Model 생성 단계에서 지원한다. C++ 코드 변경은 재빌드가 필요하며 에디터에서 소스 코드를 수정·핫리로드하는 기능은 없다.

에디터에서 실제로 확인하는 순서
  1. 객체를 선택하고 Inspector의 Add Component를 누른다.
  2. Move Component를 선택하고 Move speed를 수정한다.
  3. Ctrl+S로 저장한다. Open으로 다시 열면 컴포넌트와 값이 복원된다.
  4. Play에서 WASD 이동을 시험한다. Stop은 편집 상태로 돌아온다.
  5. Remove component로 제거하고 Ctrl+Z / Ctrl+Y로 복구·재적용한다.

폴더를 볼 때의 기준

폴더 / 파일용도
src/엔진과 에디터, 컴포넌트의 C++ 코드. Sandbox는 예제 콘텐츠, Tests는 회귀 검증.

새 콘텐츠 컴포넌트를 추가하는 순서
  1. Component를 상속하고 필요한 Awake/Start/FixedUpdate/Update를 작성한다.
  2. 저장할 설정값을 정하고 DescribeComponent와 Property로 등록한다.
  3. 새 소스가 있으면 Visual Studio 프로젝트에 포함하고 빌드한다.
  4. 에디터에서 객체에 붙여 값을 수정한 뒤 저장·재열기·Play/Stop을 확인한다.
  5. 새 자료형·리소스 의존성이 있다면 해당 편집·직렬화 지원을 먼저 추가한다.
